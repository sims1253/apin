## 1. End-to-end pipeline

Documented in docs/hacking.md:66–136 ("Life of a gradient") and README.md:73–84.

```
model.stan + data.json
  | stanc3 (OCaml, linked in-process)          runtime/src/stanc_embed_c.cpp
  v optimized transformed MIR (--O1), s-expression text
  | mir_reader.cpp -> mir::Program              runtime/src/mir_reader.cpp, include/stanli/mir.hpp
  v lower.cpp: Lowering::run()                  runtime/src/lower.cpp:4910–5024
  |   graph passes (inplace/fwd, constfold, reroll, inplace, partition, inplace, elide, cse, island)
  |   reduce_terms -> result_slot
  v CompiledModel { Graph, views, fills, write_array }   include/stanli/compile.hpp:32–200
  | Executor(Graph) -> bind_(): arenas, KernelCtx, dispatch tables   runtime/src/executor.cpp:128–282
  v forward sweep = log density; reverse sweep = gradient
  | nuts.cpp (stan::mcmc::adapt_diag_e_nuts)    runtime/src/nuts.cpp
  v draws; write_array graph or WaInterp produces CSV columns
```

- **stanc3 in process**: runtime/src/stanc_embed_c.cpp (37 lines) is the C bridge.
  `stanli_stanc_tmir()` calls `caml_startup` once, then OCaml callback
  `stanc_compile_tmir`, returning `OK<sexp>`/`ERR<msg>`. OCaml object built by
  tools/stanc_embed/build.sh via dune `--profile release -output-complete-obj`
  → deps/stanc3/stanc_embed.o; wired via `STANLI_STANC_EMBED_OBJ` +
  `stanli_embed_stanc()` (CMakeLists.txt:333–351). Non-embed builds run a
  `deps/stanc3/stanc` binary as subprocess.
- **MIR parse**: mir_reader.cpp (782 lines) parses s-expressions (sexp.hpp) into
  mir::Expr/Stmt/FunDef/Program (include/stanli/mir.hpp:32–301). Retains
  `adlevel` (data_only/promoted), `fn_propto` (`(FnLpdf true)` = `~` form),
  `Transform::Kind` (constraint-transform tags, mir.hpp:153–177). Anything
  outside the recognized slice is kept as `raw` text and becomes a loud
  CompileError, never a miscompile.
- **MIR interpreter** (include/stanli/mir_interp.hpp, 2104 lines): name-based
  tree-walker used where the graph cannot go — transformed data at load,
  DataOnly constant evaluation, ODE RHS fallback, interpreted write_array
  fallback (wa_interp.cpp).
- **Lowering**: lower.cpp (5099 lines) — struct Lowering (line 340),
  emit_raw() (1913), const_slot() (493), static name→opcode table
  (~2820–2935 for densities; entries generated by expanding the same X-macro
  lists in optable.hpp). Loops with data-known bounds are unrolled; `~`
  lowers to propto + per-argument-activity instantiations matching CmdStan's
  generated C++; parameter-dependent control flow compiles to a
  register-machine island (`lower_param_ifelse`, lower.cpp ~4780–4798);
  reduce_terms (4810–4833) sums target + jacobian terms with a 6-ary ADD_N
  tree. A second lowering builds the forward-only write_array graph
  (run_write_array, lower.cpp:4839–4908).
- **Entry point**: `compile_model(tmir_text, data)` at lower.cpp:5029.
  Consumers: runtime/src/capi.cpp:71–102 (`stanli_model_new` → compile_model
  → `make_unique<Executor>(std::move(cm.graph))`) and bridgestan_abi.cpp.

### The in-memory IR after lowering

`runtime/include/stanli/graph.hpp` — "the runtime's IR and, during reverse mode, its tape":

- **Slot** (graph.hpp:33–37): `{int64_t offset; int64_t len; bool is_param}` —
  offset into the value arena, filled at bind. Parameter slots are laid out
  first, in declaration order, so the gradient is one contiguous vector.
- **Op** (graph.hpp:39–56):
  ```cpp
  struct Op {
    uint16_t opcode;      // Opcode enum from optable.hpp
    uint8_t variant;      // density: bits 0..5 per-arg activity, bit 6 elementwise-lp, bit 7 propto;
                          // other kernels: ODE scalar types, RNG family, etc.
    int out;              // output slot index
    int out2;             // optional 2nd output (constrain Jacobian term)
    int in[6];            // input SLOT indices (not arena offsets)
    int n_in;             // hard ceiling of 6, checked in Graph::add_op
    const int* idata;     // integer immediates (index arrays, dims, discrete outcomes)
    int64_t n_idata;
    const void* udata;    // opaque payload (IslandProg, ODE spec, MessageSpec, CategoricalSpec...)
    int64_t scratch_off, scratch_len;  // per-op scratch window, filled at bind
  };
  ```
  Operand model: slot indices, not raw pointers; immediates are integers
  (idata); constants are len-1 fill slots (double immediates arrive via slot
  fills written at bind from CompiledModel::fills — compile.hpp:155–162).
  Real-number immediates therefore live in the value arena, not in the op.
- **Graph** (graph.hpp:58–94): `vector<Slot> slots; vector<Op> ops; vector<vector<int>>
  idata_pool; vector<shared_ptr<void>> udata_pool; int result_slot`. Add-op
  enforces the 6-input ceiling with a length_error.
- **KernelCtx** (graph.hpp:98–114): per-op runtime view assembled once at bind —
  `Desc in[6]` ({double* data; int64_t len}), out/out2, variant, scratch,
  idata, udata, EvalState*, plus backward-only in_adj[6] (null Desc for data
  inputs), out_adj (scalar), out_adj_vec, out2_adj.
- Payload types: MessageSpec, BoundCheckSpec, CategoricalSpec (graph.hpp:119–140);
  island payloads are IslandProg (include/stanli/island.hpp:42–69).

Opcode vocabulary: include/stanli/optable.hpp (835 lines) — enum from X-macro
lists: STANLI_OPCODE_LIST (13–155 hand ops), STANLI_SCALAR_DENSITY_LIST
(201–240), STANLI_INT_DENSITY_LIST (252–256), CDF lists (290–440),
STANLI_ORDERED_DENSITY_LIST (454–455), STANLI_SCALAR_UNARY_LIST (486–576,
each line carries fn, value expr, hand-written `delta` derivative, and
UnaryTopology), STANLI_SCALAR_BINARY_LIST (587–605). Opcode enum 671–681
(~250 opcodes); rewrite-safety traits op_trait::kRerollDensity /
kRerollIdataDensity / kRerollWidenable / kBackwardValueFree at 684–775;
is_effectful_op at 786–800.

**Example lowered op sequence** (docs/lowering-walkthrough.md:101–111, linear
regression N=5; `build-rel/dump_ops ex1.sexp ex1.json`):

```
slots=16 ops=8 result=15
    0 CONSTRAIN_LOWER v=00 out=s5(len1) in=s2(l1,P),s3(l1)
    1 MUL         v=00 out=s8(len5) in=s1(l1,P),s7(l5)
    2 ADD         v=00 out=s9(l5) in=s0(l1,P),s8(l5)
    3 NORMAL_LPDF v=86 out=s10(len1) in=s6(l5),s9(l5),s5(l1)
    4 NORMAL_LPDF v=81 out=s12(len1) in=s0(l1,P),s3(l1),s11(l1)
    5 NORMAL_LPDF v=81 out=s13(len1) in=s1(l1,P),s3(l1),s11(l1)
    6 NORMAL_LPDF v=81 out=s14(len1) in=s5(l1),s3(l1),s11(l1)
    7 ADD_N       v=00 out=s15(len1) in=s10,s12,s13,s14,s4
```
`P` marks parameter slots; `v=86` hex = propto(bit7=0x80) + args 1,2 active
(0x06); `v=81` = propto + only arg 0 active. A `for (n in 1:N)` loop lowers to
exactly the same 8 ops after unroll-then-reroll (walkthrough §Layer 2½).

There is a **second, lower-level IR**: the register machine `Program`
(include/stanli/program.hpp:108–177: vector<Instr> with 24-byte instructions
{Code, dst,a,b,c, len}, vector<Call> payloads, double pool constants,
out_regs), used by tape islands, parameter-dependent control flow, and ODE RHS
(ode_prog.cpp). ~35 opcodes incl. jumps (JZ/JMP), one DENSITY instruction (any
of 27 scalar densities via program_density.hpp), and CALL which invokes any
graph kernel over register ranges (executor.cpp:74–92).

## 2. Graph passes

**Pipeline driver**: Lowering::run() in lower.cpp:4910–5024 — passes invoked
inline, in this exact order, each traced by a PrepTrace ("prep graph" profile
hook, STANLI_PROFILE_PREP=1; stages via tools/bench_grad.cpp --prep):

1. bind_data (4914)
2. lower (4917–4920)
3. **inplace** — make_inplace_updates(g, update_roots) (4930–4935)
4. **store-to-load forwarding** — forward_stores_to_loads(g, update_roots) (4938–4942)
5. **constfold** — const_fold(g, out.fills, update_roots) (4945–4950)
6. **reroll** — reroll(g, out.fills, target_terms, roots) (4951–4957)
7. **post_reroll_inplace** (4963–4968, only if reroll rewrote)
8. **partition** — partition_lanes(g, ...) (4972–4978)
9. **post_partition_inplace** (4984–4990)
10. **elide_stores** — elide_full_extent_stores (4994–4997)
11. **cse** — cse(g, out.fills, target_terms, roots) (5001–5004)
12. **island** — carve_islands(g, ...) (5008–5012, LAST)
13. reduce — reduce_terms builds the ADD_N tree, sets result_slot (5013–5018)

All passes operate **in place on the linear op sequence (Graph&)** — no
separate SSA/CFG. Roots (jac_slots, parameter views, target terms) must be
passed explicitly because they have no consuming op; an incomplete list is a
miscompile (reroll.hpp:41–46). The write_array graph runs a reduced pipeline
(run_write_array, lower.cpp:4863–4896: inplace → store_forward → reroll →
post_reroll_inplace).

Per pass (headers + OPTIMIZATIONS.md):

- **inplace.cpp** (STANLI_NO_INPLACE=1; OPTIMIZATIONS.md:65–106). Destructive
  functional updates: `mu[n] = x` unrolls to whole-vector copies (O(N²)); if
  the write is the last use of the buffer and no earlier reader's *backward*
  rereads values (kBackwardValueFree trait whitelist in optable.hpp:758–771;
  the check backward_ignores_values in inplace.cpp), the op becomes
  OP_SET_*_INPLACE with out slot aliased to in slot. Without the reverse-sweep
  rule, 8 models were silently wrong by up to 1.7e5 relative. Also does
  store-to-load forwarding (OPTIMIZATIONS.md:108–116).
- **constfold.cpp** (STANLI_NO_CONSTFOLD=1; OPTIMIZATIONS.md:118–133). Finds
  ops no parameter reaches, executes them once through a real Executor over a
  sub-graph (the kernel is the single definition of semantics), deletes the
  ops, replaces buffers with final values in fills. Order-sensitive: refuses
  slots that a surviving op reads mid-overwrite-chain.
- **reroll.cpp** (STANLI_NO_REROLL=1; OPTIMIZATIONS.md:135–218). The main
  vectorizer. Detects N consecutive copies of a periodic op template (lanes;
  kMinLanes=4, kMaxPeriod=32, reroll.cpp:57–59). Input classification
  INVARIANT / CONST_LANES / LANE_LOCAL; indexed reads become slices/gathers
  (OP_GATHER), marching writes become one store, N scalar target-bound
  densities become one summed vector density, mixture-shape densities become
  elementwise (variant bit 6). Narrow pre-pass recognizing fixed-width LDA
  row-reduction grammar (OP_LOG_SUM_EXP_ROWS). radon_pooled: 27,670 ops → 8.
  Failing classifications retry on the longest classifiable lane prefix
  (handles block-sorted data).
- **partition.cpp** (STANLI_NO_PARTITION=1; OPTIMIZATIONS.md:220–293;
  partition.hpp). Lane bucketing without adjacency/periodicity: computes where
  a lane *ends* (target term or element store), groups lanes by structural
  fingerprint, rewrites each bucket in place with slices/gathers/shared
  operands; cost model (~5 ns/op vs ~1 ns/element, densities 6 dispatches),
  declines unprofitable buckets. GLM-recognition arm rewriting cumsum/slope
  chains into categorical_logit_glm_lpmf rows. state_space_...seasonal:
  1,375 ops → 19.
- **cse.cpp** (STANLI_NO_CSE=1; OPTIMIZATIONS.md:295–325). Local value
  numbering made safe for mutable-buffer slots: per-slot version numbers in
  the key, single-writer outputs only, effectful/opaque-payload ops never
  merge (never_merge, cse.cpp:34–38). Lazy renaming one forward pass.
  Mt_model: 1,062 → 70 ops.
- **island.cpp** (STANLI_NO_ISLAND=1; OPTIMIZATIONS.md:647–722; island.hpp).
  The carver: takes maximal runs of leftover scalar residue (cross-lane
  recurrences: HMM forward algorithms, state-space updates) and compiles them
  into a single OP_ISLAND whose udata is an IslandProg register program, plus
  INDEX/SLICE ops for live-outs. Commits only when a cost estimate (registers
  written+read, both instruction lists, per-op dispatch tax, adjoint
  equivalence classes) says the island wins; STANLI_ISLAND_ALWAYS=1 skips the
  estimate, STANLI_DEBUG_ISLAND=1 prints verdicts. Refuses: <32-op runs,
  >6 distinct inputs, propto densities, regions producing target entries;
  branches on parameters keep the var-replay backward. Register-program
  compaction (compact_program, program.cpp, STANLI_NO_ISLAND_COMPACT) runs first.
- **adjoint.cpp** (adjoint.hpp). NOT a graph pass: the source-transformation
  differentiator for register programs. gen_adjoint(IslandProg&) reads the
  forward instruction list and emits an AdjProgram (AdjInstr{code, mask,
  dst,a,b,c, len, vd,va,vb,vc}, adjoint.hpp:45–54) computing the reverse
  sweep in plain doubles, allocating nothing. Every rule transcribes the
  stan-math rev expression operand-for-operand for bitwise agreement with the
  var replay; checkpoint analysis inserts value-saves (e.g. MOVR) where a
  later write destroys a value a derivative rule needs. STANLI_NO_NATIVE_ADJ=1
  restores the nested-var replay (the test oracle, tests/test_adjoint.cpp).

OPTIMIZATIONS.md (87 KB) documents each transformation: motivating model,
mechanism, per-pass env kill switches, targeted measurements, cost models,
deferred reassociation candidates (2026-08-25 precision survey, lines 910–955),
how everything is checked (957–981), historical measurement appendices.

## 3. Execution model

**runtime/src/executor.cpp** (424 lines):

- Kernel table: `static Kernel g_table[OP_COUNT_]` (line 18);
  register_kernel() (56–59) called by per-TU register_*_kernels() functions
  from ensure_registered() (108–126) at static-init/first-use. Kernel = 3
  function pointers: forward, backward, scratch_size (optable.hpp:806–814).
- Executor::bind_() (144–243), run once at construction:
  - lays out the value arena: param slots first (contiguous gradient), then
    everything else; values_.assign(off, 0.0).
  - lays out a compact adjoint arena: parameters first, then only slots
    written by some op or the result slot (written[]); data and dead rewrite
    slots get no adjoint cell (in_adj[k].data == nullptr → kernel skips). On
    iohmm_reg: 1,604,979 adjoint doubles → 3,084.
  - sizes the scratch arena by summing each op's Kernel::scratch_size,
    assigns scratch_off.
  - assembles one KernelCtx per op (make_ctx_, 245–282) — every field is a
    pointer into a never-moving arena or an immediate; per-evaluation work is
    only refreshing two scalar adjoints.
  - resolves dispatch tables: fwd_fn_ (forward fn per op) and bwd_
    (BwdStep{fn, ctx, out2_adj*} in reverse order, backward-less ops dropped)
    — graph.hpp:226–246.
- Forward sweep (run_forward_only, 322–362): hand-unrolled 4-wide
  indirect-call loop over fwd_fn_ (measured win over musttail threading;
  tools/bench_dispatch.cpp keeps the comparison). forward() (372–377) returns
  values_[result_slot]. forward_value_only() sets a thread_local flag so
  kernels may skip backward-only work (initialization validity checks mirror
  CmdStan's double path).
- Reverse sweep (gradient(double* grad_out), 379–422): forward(), memset the
  adjoint arena to 0, seed adjoints_[result_adjoint_offset_] = 1.0, run bwd_
  in reverse (same 4-wide unroll; each step refreshes ctx.out_adj /
  ctx.out2_adj from the arena, since kernels take them by value), then
  memcpy the first n_params_ adjoints out as the gradient. Steady-state
  gradient evaluation performs zero allocation; the op list itself is the
  tape (nothing recorded per evaluation).
- Profiling: opt-in per-opcode accounting (set_profile, profile_report);
  STANLI_PROFILE=1 in CLI tools.

executor_pool.cpp / .hpp: executors are not thread-safe (arenas are
per-evaluation mutable state). ExecutorPool::acquire() clones a prototype
executor (copy ctor copies graph + arena *contents*, executor.cpp:133–142)
under a scoped lease, installs a thread_local stan::math::ChainableStack on
caller threads (required for nested tapes in legacy kernels/islands under
STAN_THREADS). Used by the BridgeStan facade and multi-chain sampling
(capi.cpp:379+).

adjoint.cpp (island backward): run_adjoint(fwd, ap, val, adj) walks
AdjProgram::code in reverse over the adjoint file; the island op's scratch
slice *is* its register file, so forward values/checkpoints survive into the
backward; seeding/harvesting goes through the copy-equivalence map adj_reg.

Memory: three arenas (values_, adjoints_, scratch_) + per-op contexts, all
allocated once at bind; legacy ops and var-replay islands are the exceptions
(nested stan-math tape, arena-allocated, recovered per call).

## 4. Kernel library

Two tiers, one interface (README.md:117–123):

- **Native kernels** (runtime/kernels/): hand-written forward/backward pairs
  that mirror stan-math's rev Eigen expressions exactly. Files:
  elementwise.cpp (structural/elementwise: EXP, ADD_N, BCAST_FMA, MATVEC,
  GATHER...), eltwise_expr.cpp (shape-dispatched elementwise arithmetic),
  densities*.cpp (sharded density instantiations), constrain.cpp,
  matrix_fns.cpp (linear algebra + native eigen pullbacks), mixture.cpp
  (log_sum_exp/log_mix with value-free backwards), scalar_binary.cpp,
  scalar_unary_ad.cpp, message.cpp (categorical/reject/print), rng.cpp,
  island.cpp (the OP_ISLAND kernel), ode.cpp.
- **Legacy ops** (include/stanli/legacy.hpp, runtime/kernels/legacy_fns.cpp,
  parts of matrix_fns.cpp): run unmodified stan-math templates.
  legacy_fwd_partials_vec computes value+partials in the forward on a
  var_value<VectorXd> nested tape and stashes partials in scratch;
  legacy_bwd_vec_in replays with the dot-trick vjp. Correct by construction,
  allocates per call; everything the corpus needs but nothing native yet.

**normal_lpdf path (primal + adjoint)** — density machinery in
runtime/kernels/densities_impl.hpp:

- One list line `X(OP_NORMAL_LPDF, normal_lpdf, 3, 3)` in optable.hpp:202
  generates: the opcode, forward normal_lpdf_fwd_gen
  (densities_common_a.cpp, via STANLI_DEFINE_DENSITY_FWD,
  densities_impl.hpp:327–332), registration (densities.cpp:10–13:
  Kernel{fn##_fwd_gen, density_bwd<3>, density_scratch<3>}), and the lowering
  table entry in lower.cpp.
- Forward density_fwd_v<3, tier> (densities_impl.hpp:222–244): scratch layout
  = one partial per element of each argument, contiguous (sink_for_args,
  36–46) + a connected flag. Reads the variant byte: mask = variant & 0x3f
  (which args are autodiff), bit 7 = propto. mask_dispatch (93–102) selects
  the compile-time Mask instantiation; bind_args_m (59–90) binds each active
  arg as an rvar (scalar or as_rvar vector — a zero-copy
  Eigen::Map<const Matrix<rvar>> view of the arena) and each data arg as
  plain double/VectorXd, then calls stan-math's own
  stan::math::normal_lpdf<propto>(...) template inside
  record_probability_call. Bit 6 selects the elementwise form
  (density_fwd_elt, 164–189): one scalar recorder call per lane, partials
  aimed straight at [k*N + n] scratch slots so fused lanes are bit-identical
  to the scalar ops they replace.
- The magic is the recorder scalar rvar (include/stanli/recorder.hpp): a
  double-sized POD registered as stan::is_fvar with partials_type = double
  and a specialized partials_propagator whose build() deposits the
  operands-and-partials into a thread-local sink (recorder.hpp:239–271). No
  tape, no varis. rvar deliberately has no arithmetic operators so functions
  that do arithmetic on the scalar type (von_mises_cdf, neg_binomial_2_lcdf)
  fail to compile and get routed to a nested var tape instead.
- Backward density_bwd<N> (densities_impl.hpp:252–286):
  in_adj[k] += out_adj * Map(scratch + off_k) for each active arg with
  non-null adjoint; elementwise variant scales column k by per-element
  out_adj_vec and sums broadcast columns descending to match the reverse
  sweep's accumulation order bit-for-bit.
- Bitwise parity with CmdStan: (a) same library — kernels call the same
  stan-math templates; (b) -ffp-contract=off pinned on the stanmath interface
  target project-wide (CMakeLists.txt:109–113; -ffp-contract=fast measured a
  1.7% slowdown and perturbs 101/120 models); (c) kernels transcribe
  stan-math's rev expressions operand-for-operand, including summation
  direction (kernel contract in hacking.md:231–262: "add numbers in the same
  order the reference does"; e.g. fma_bwd accumulates descending,
  elementwise.cpp:52–66); (d) per-argument activity masks reproduce exactly
  the data/parameter template combination CmdStan instantiates, so propto
  term-dropping matches. Result: 41 corpus models bitwise-identical on
  lp+gradient, worst deviation 2.6e-12 (docs/corpus-status.md). Deliberate
  exceptions recorded at call sites (elementwise log packet path, 1 ULP).
  STANLI_PACKET_MATH=1 (varmat/packet kernels, packet.hpp) exists but is OFF
  by default — measured neutral and costs parity.

Instantiation explosion: each density instantiates 4·2^N templates
(mask × propto × elementwise), ~630 KB per 3-arg density; shard TUs
(densities_common_{a,b}.cpp, densities_rest_{a,b}.cpp, densities_lpmf.cpp,
densities_glm.cpp, densities_cdf_{a,b}.cpp) exist because one TU peaked at
7.6 GB compiler memory. Tier bits in the list (optable.hpp:189–240) control
the ladder; STANLI_LITE_LP drops the propto family.

## 5. Samplers

- nuts.cpp (189 lines): Stan's own stan::mcmc::adapt_diag_e_nuts<ExecutorModel,
  rng_t> driven through model_adapter.hpp (ExecutorModel adapts the executor
  to Stan's model concept). RNG constructed CmdStan's way
  (stan::services::util::create_rng(seed, chain_id)), init matches CmdStan's
  uniform(-2,2)+validate-retry. Parallel chains = one executor per chain in
  std::threads, byte-identical to sequential.
- walnuts.cpp (204 lines): WALNUTS — "within-orbit adaptive step-length NUTS"
  (arXiv:2506.18746) via vendored headers runtime/third_party/walnutpie/.
  Unlike NUTS's one step size per chain, WALNUTS halves the step within a
  trajectory where local error demands (config: max_step_halvings, max_error,
  trajectory-doubling cap max_depth, Adam-adapted init step). Only C++20 TU
  in the runtime; deliberately includes no stan-math. Exposed as
  stanli_sample_walnuts_stream (capi.h:270).
- pathfinder.cpp (278 lines): wraps stan::services::pathfinder over the
  executor; writes lp_approx__/lp__/path__ + constrained columns.
- Also diagnose.cpp (CmdStan-style diagnostics in words), estimate.cpp
  (stansummary table).

## 8. Extension points

**(a) Adding a native kernel.** Recipe at docs/hacking.md:386–447:
- Density/CDF/scalar function = one line in the matching X-macro list in
  optable.hpp (STANLI_SCALAR_DENSITY_LIST etc.) — generates opcode + name +
  kernel + registration + lowering entry simultaneously (cannot drift).
  Functions that do arithmetic on the AD scalar (von_mises_cdf) go on
  STANLI_TAIL_CDF_LIST / nested-tape paths instead.
- Anything else: 4 steps — (1) opcode in optable.hpp + kernel TU in
  runtime/kernels/ (wrap stan-math via legacy.hpp if no native port; implement
  Kernel{forward, backward, scratch_size}; register in the TU's
  register_*_kernels() added to ensure_registered() in executor.cpp:108–126);
  (2) a lowering branch/table entry in lower.cpp's static fn table (~2820–2935)
  or lower_*_fn; (3) a parity test vs the same call on stan::math::var;
  (4) read dump_ops output. Kernel contract (null in_adj, summation order,
  private scratch) at hacking.md:231–262.

**(b) Where a JIT/codegen backend could intercept; existing hooks.**
- The clean seam is CompiledModel::graph between compile_model()
  (lower.cpp:5029) and Executor construction — concretely capi.cpp:71–72
  (`m->cm = compile_model(...); m->ex = make_unique<Executor>(std::move(cm.graph))`)
  and the same for the write_array graph (capi.cpp:102). By that point the
  graph is post-pass, fully resolved (every opcode, slot length, variant,
  scratch size load-time final; "no decision remains inside it" —
  lowering-walkthrough.md:194–197). The Executor deliberately re-exposes
  graph() and param_ptr/value_ptr (graph.hpp:169–178) so a second consumer
  can exist without re-lowering.
- The Kernel function-pointer is the unit of codegen: Executor::bind_
  resolves per-op forward/backward pointers into fwd_fn_/bwd_
  (executor.cpp:232–242). A compiled per-region function could be installed
  exactly like a kernel: either as a fused OP_ISLAND-style op replacing a
  region (the island carver is the existing region-extraction machinery,
  island.cpp + compact_program), or by replacing entries in the dispatch
  vectors. Precedent inside the repo: islands + gen_adjoint already ARE a
  load-time compiler over a region IR with a cost model, and Program::CALL
  (executor.cpp:74–92) shows how arbitrary kernel code is invoked out of a
  register file.
- There is no AOT/JIT/serialization of the lowered program today. README is
  explicit: "There is no JIT and no C++ codegen; 'compiling' a model takes
  milliseconds" (README.md:69–71). No LLVM anywhere.
- Pass kill switches (STANLI_NO_*) and STANLI_PROFILE_PREP=1 (per-stage prep
  timing via PrepTrace in lower.cpp; measured with bench_grad --prep) are the
  debugging hooks for anything inserted into the pipeline.

**(c) Existing caching.**
- No on-disk cache of lowered graphs or evaluated artifacts. The only
  persisted "compiled" artifact is MIR text: the BridgeStan facade accepts a
  JSON data argument carrying a __stanli manifest {build_id, mir, name}
  (bridgestan_abi.cpp:415–473, validated by bs_read_manifest at 264–286) —
  callers cache the stanc3 output, not the graph; lowering always re-runs.
- STANLI_BUILD_ID (CMakeLists.txt:226–239: abi1-<git sha>-<os>-<arch>
  [-litelp][-threads]) exists "for callers that cache artifacts next to the
  library"; manifest reads refuse a mismatched build.
  stanli_abi_version()/STANLI_ABI_VERSION gate binding layout.
- In-memory compile-time memos only: const_cache/effectful_cache in
  lower.cpp:375,393; const-fold results recompute each load.
- Historical: a browser "density pack" with stanli_register_kernel_c (runtime
  kernel registration from JS) was built and removed — docs/density-pack.md
  records why (emscripten limitation); shows the kernel table was once
  externally extendable at runtime.

## 10. Surprising / heavy things a compiler engineer should know

- **Per-argument activity masks** are the central compile-time/run-time
  bridge: Op::variant bits 0–5 = which density args are autodiff; kernel side
  expands to 2^N template instantiations at stanli build time (mask_dispatch),
  ×2 propto ×2 elementwise = 4·2^N explosion dominating the 29.7 MB binary and
  build time. A codegen layer that fuses densities must preserve mask/propto
  semantics or lp__ drifts by a constant while gradients stay perfect (the
  nastiest bug class per hacking.md:226–229).
- **The recorder (rvar)** is an elegant AD interface: a double-layout POD
  registered as stan::is_fvar with a partials_propagator that dumps per-edge
  partials into a thread-local sink — stan-math's prim probability functions
  compute value and partials entirely in doubles, no tape for native
  densities. No operators by design: scalar-arithmetic-on-AD-type functions
  fail to compile rather than misbehave.
- **Bitwise-parity discipline is pervasive and load-bearing**: summation
  direction specified per kernel (descending accumulations mirror the var
  tape's reverse order); -ffp-contract=off project-wide; STANLI_PACKET_MATH
  and Eigen gemv/gemm reassociation measured and declined
  (OPTIMIZATIONS.md:910–955 "Deferred: reduction reassociation" is
  effectively the list of fusion opportunities a JIT must NOT take without
  accepting ULP drift). A fusion/codegen layer inherits the same constraint:
  reordering any reduction moves models out of the bitwise band.
- **In-place pass legality depends on backward semantics**: only ops with the
  kBackwardValueFree trait may precede a destructive write — per-op whitelist
  in optable.hpp:758–771, test-enforced. Any new fused kernel must decide its
  trait.
- **The ODE story**: RHS is a user function that can't be inlined (integrator
  picks times), compiled into the shared register machine (ode_prog.cpp +
  mir_prog.hpp), with the MIR interpreter as fallback. The ODE kernel
  (kernels/ode.cpp) solves the coupled states+sensitivities system in the
  forward and stashes the Jacobian so the backward is a matvec, exploiting
  stan-math's precomputed-gradient varis. ODE models are the one class still
  slower than CmdStan (0.87–0.90x).
- **Three engines, one rule**: MIR interpreter (decides everything late; must
  always speak more of the language than the fast path), op graph (shapes/
  order early), register machine (placement early; may branch). wa_interp.cpp
  is the per-draw write_array fallback keeping that invariant.
- **The executor's compact adjoint arena** excludes data and dead slots, so
  the per-gradient reset is one memset over only live cells;
  adjoint_storage_size() intentionally observable so rewrites can't silently
  grow it.
- **Dispatch micro-optimizations are measured, not assumed**: 4-wide manual
  unroll beat tail-call threading; contexts preassembled once (~300 B/op/sweep
  saved); value-slot tombstone compaction tried and slowed a model 8% by
  shifting hot buffers (OPTIMIZATIONS.md:883–908) — relevant if a codegen
  pass wants to renumber slots.
- TBB is stubbed out (tests/tbb_stub.cpp); STAN_THREADS makes stan-math's
  stack thread_local; executor_pool.cpp installs ChainableStack on caller
  threads. walnuts.cpp is the lone C++20 TU.
- Env kill switches (all STANLI_NO_*): DATA_PRELOAD, INPLACE, CONSTFOLD,
  REROLL, PARTITION, CSE, ISLAND, ISLAND_COMPACT, NATIVE_ADJ — plus
  STANLI_ISLAND_ALWAYS, STANLI_DEBUG_ISLAND, STANLI_DEBUG_ODE,
  STANLI_DEBUG_INIT, STANLI_PROFILE, STANLI_PROFILE_PREP,
  STANLI_PACKET_MATH. Every optimization number in the docs is the same build
  with one switch toggled.
- The roadmap (README.md:394–417, docs/superpowers/plans/
  2026-08-08-cmdstan-parity-roadmap.md) already names the engine-level future
  work: fusing adjacent elementwise chains into one pass over the arena
  (explicitly listed as next, now that reroll covers the mixture shape and
  islands compile the scalar residue) and varmat (SoA) kernels — both
  directly adjacent to a codegen/fusion layer.

## Where to hook a JIT, in one paragraph

Lower `compile_model()`'s output point: after Lowering::run() finishes the
pass pipeline and reduce_terms (lower.cpp:5013–5023) the Graph is a closed,
final data structure (fixed opcodes, slot lengths, variants, scratch sizes,
immediates in idata_pool/fills). A codegen backend can (1) consume Graph and
emit one fused forward function + one fused reverse function for whole
regions — the legality facts it needs already exist as op_traits and the
island carver's region finder; (2) install the results through the existing
Kernel/dispatch-vector seam (fwd_fn_/bwd_, or a single island-style op),
needing no executor changes; (3) key any artifact cache on STANLI_BUILD_ID +
a graph hash, mirroring the __stanli manifest pattern. The register machine
(Program + gen_adjoint) is both precedent and reusable infrastructure: it is
already a load-time source-transforming compiler with checkpoint analysis and
a cost model, and dump_ops/dump_islands give ground-truth views of exactly
what would be fed to codegen.
