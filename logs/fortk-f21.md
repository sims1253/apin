## Pre-registered design (stated BEFORE any screening run)

THE KNOB (mechanism-driven): an explicit frozen-step MULTIPLIER, applied
POST-FREEZE only. walnutpie's AdaptiveWalnuts::sampler() hands Adam's final
step to WalnutsSampler as the macro time, as-is. A scale by K there
emulates the stock regime's large frozen steps (stock 0.22 ~ b10's 0.057 x
4) while keeping the denoised batched estimator during warmup. Crucially
the multiplier must NOT apply during warmup: Adam sees acceptance stats
generated by the trajectories it steers, so a during-warmup scale would be
absorbed (Adam compensates to step/K) — exactly the coupled-calibration
trap F-11.2 documented. Post-freeze there is no feedback (sampling uses
NoOpStepSizeAdapter), so the scale sticks.

Plumbing (default-off = multiplier 1.0, byte-identical path):
- vendored config.hpp: WarmupConfig.step_freeze_multiplier_ (default 1.0),
  accessor, builder setter validate_finite_positive;
- adaptive_walnuts.hpp sampler(): frozen = step_size(); if (mult != 1.0)
  frozen *= mult; — used for BOTH on_warmup_complete() reporting and the
  WalnutsSampler macro time (guarded multiply so the default path executes
  no new arithmetic at all);
- stanli WalnutsConfig.step_freeze_multiplier = 1.0 + walnuts.cpp builder;
- regions.cpp: --w-step-mult K (walnuts arm only) + SAMPLE_W_ADAPT field
  + CSV f112(...) tag extension;
- test_walnuts_adapt: multiplier-scales-frozen-step + default==stock
  property cases (inside the existing TU; suite count unchanged).

SELECTION RULE (pre-registered, binding):
- SCREEN GRID: batch {10, 25} x multiplier {1, 2, 4, 8}, target 0.8
  (fixed; the target side is pre-registered as fallback-only), PLUS a
  D_stock reference arm (batch 1, mult 1) for same-day mechanism numbers.
  Dev set {esnc, blr, kidscore, logmesq}, pf-init, 4 chains x 1000+1000,
  1 REP ONLY for screening (stated: single-rep, no rep noise band).
- ELIGIBILITY (both required): (i) all-chain R-hat < 1.01 on EVERY dev
  model; (ii) kidscore ESS/draw (bulk geomean / 4000) >= 0.1.
- RANKING METRIC: geomean over the 4 dev models of the ESS/s PROXY
  P = ESS/draw x frozen_step, where frozen_step is the median across
  chains of the CSV stepsize__ column (the ACTUAL post-multiplier frozen
  step; load-stable, draw-based). Rationale: F-11.2 measured work ~
  1/frozen_step (blR stock 0.214-0.225 vs b10 0.057 = ~3.5x wall), so
  ESS/draw x frozen_step estimates ESS/s off load-stable quantities only.
  Interleaved wall is RECORDED (labeled noisy; F-20 callgrind agent
  shares the box) as a sanity check, NOT the ranking metric.
- WINNER = highest geomean P among eligible configs. If NO config is
  eligible, the campaign is a miss -> mechanism write-up, no tuning past
  the grid. Tie-break (within 5%): the config with fewer effective
  micro-steps (smaller batch x mult product) — cheaper.
- Widening beyond the grid (target 0.9, other K) ONLY if the write-up
  demands it, and only as a recorded addendum, never as gate-bait.

## MECHANISM WRITE-UP (the miss, ranked)

1. THE GLOBAL MULTIPLIER CANNOT FIT THE FLEET — the optimal frozen-step
   scale is model-specific, and the grid's two ends are each other's
   poison:
   - esnc peaks at K=4 (screen ESS/draw 1.545) and collapses at K=8
     (0.195; trajectories U-turn after ~1 macro step at macro time 5.33
     — cheap draws, no exploration: D/A 0.71x today despite the cheapest
     draws of any arm).
   - logmesq NEEDS K=8 for rhat (K=4: 1.015 -> K=8: 1.002 screen;
     ESS/draw 0.090 -> 0.417, 4.6x stock) and kidscore needs >= K=4
     (ESS/draw 0.133 -> 0.457 at K=8).
   The screen's eligibility filter therefore selected exactly the config
   that sacrifices esnc — the filter was applied as pre-registered, and
   the validation confirmed the sacrifice propagates to the geomean.
   The screen proxy (ESS/draw x frozen step, work ~ 1/step) OVERSTATED
   m8: the work-vs-step law breaks at large K where the U-turn truncates
   trajectories (work per draw collapses, not grows) — the noisy-wall
   column showed this (m8 walls ~ m4 walls) and was recorded but not
   ranked on, as pre-registered.
2. THE F-16 SILENT-FAILURE SET MOVES THE RIGHT WAY BUT NOT FAR ENOUGH.
   At K=8 all three improve over BOTH stock and b10 (bym2 1.055/1.027 ->
   1.017; diamonds 1.108/1.030 -> 1.015; kronecker 1.05-1.34 -> 1.047)
   — the too-small denoised step WAS part of their problem — yet none
   crosses 1.01. Their frozen steps at K=8 (0.62-1.02) sit at ~1/2 to
   ~1/5 of the phase-1 winners' (2.4-5.3): the mass/step coupling these
   models suffer (F-16's "residual = coupled target/step calibration")
   is only partially step-scale.
3. WHERE THE STEP LANDED (frozen step, stock -> b10 -> b10 x 8):
   esnc 0.706 -> 0.658 -> 5.33 | blr 0.222 -> 0.075 -> 0.59 |
   kidscore 0.504 -> 0.310 -> 2.58 | logmesq 0.336 -> 0.311 -> 2.44 |
   esc -> 4.17 | pilots -> 1.94 | bym2 -> 1.00 | diamonds -> 0.62 |
   kronecker -> 1.02. F-11.2's "denoised root is 4x smaller" was
   blr-specific: the b10/stock frozen-step ratio spans 1.07x (esnc) to
   3.0x (blr). Stock's accidental step was model-accidentally good on
   the well-conditioned models, catastrophically noisy on the others.
4. GRADS/ITER: the walnuts path carries no counter in this worktree

## WIDENING DECISION (pre-registered condition applied)

The write-up does NOT demand a target-side probe: the target acts on
the same scalar (the frozen step scale) plus the warmup-noise coupling
F-11.2 already rejected empirically (0.6/0.7 broke blr+kidscore), and
the failure mode here is BETWEEN-MODEL heterogeneity of the optimal
scale (esnc vs logmesq pull opposite) plus non-step-scale residuals on
the failure set — no global (target, K) pair fixes either. A 0.9 or
K=16 probe would be gate-bait, not mechanism. DECLINED.
